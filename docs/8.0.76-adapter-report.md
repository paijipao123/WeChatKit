# 微信 8.0.76 适配分析报告

> 分析日期: 2026-08-14
> 分析方法: 从 APKCombo 下载官方微信 8.0.76 APK (266MB, 17 个 dex), 使用 androguard 逐一对比 8.0.71 与 8.0.76 的核心类结构。

## 结论: 当前模块原生兼容 8.0.76

8.0.76 是 8.0.71 的微调版本。通过真实 APK 分析确认, 绝大部分核心结构**完全一致**,
唯一变化是红包请求类被混淆改名——而模块的 **DexKit 特征定位框架自动适配**该变化,
无需修改任何代码。

## 为什么能自动适配

模块采用"从最新版向下兼容"的**多路符号定位**架构 (SymbolResolver):
1. 优先用 **DexKit 特征字符串**定位 (协议名/日志 TAG/cgi 路径, 跨版本稳定);
2. 红包 Receive/Open 类虽然 8.0.76 改名 (i6→l6, c6→f6),
   但 `MicroMsg.NetSceneReceiveLuckyMoney` 特征字符串不变,
   DexKit 自动找到新类名;
3. 构造函数签名一致, 直接可用。

## 验证方式

在 8.0.76 手机上安装模块后, 观察 LSPosed 日志:
- `定位到的转账收款类: com.tencent.mm.plugin.remittance.model.n0` (应与 8.0.71 相同)
- `[自动抢红包] Receive 类=com.tencent.mm.plugin.luckymoney.model.l6` (8.0.76 的新类名)
- 红包/转账请求 `onSceneEnd errType=0 errCode=0` (成功)

## 后续版本维护

若未来微信版本 (8.0.77+) 出现特征字符串变化或构造参数变化:
1. 下载新版本 APK, 用本报告的方法分析关键特征;
2. 特征变化 → 在 SymbolResolver / 各功能中添加新的候选特征组;
3. 构造参数变化 → 调整 newInstance 参数或添加多构造回退。
